# 目录结构规划

本文档作为后续开发的目录标准。新增业务模块、页面、接口、共享类型和工具时，优先按本文档组织代码。

## 总体原则

```text
apps/
  backend/          后端服务
  admin-web/        管理端
  workstation-web/  员工端 / 工位端 / 检测端
packages/
  api-contract/     前后端共享接口路径和 DTO 类型
  constants/        前后端共享常量
  request/          前端 HTTP 请求基础封装
  auth-client/      前端认证客户端
  ui/               可复用 UI 组件
  utils/            纯工具函数
docs/               设计文档、权限文档、SQL 初始化脚本
```

约束：

- 业务代码按模块归档，不跨模块随意引用内部实现。
- 前后端共享的类型、接口路径、权限编码必须放在 `packages`。
- `apps/*` 内只保留应用运行时相关代码。
- 不把业务逻辑放进 `packages/utils` 或 `packages/constants`。
- 不为临时页面、临时接口新增全局公共工具，除非至少两个模块真实复用。

### 后端命名规则

- Controller 只处理路由、权限装饰器、参数读取。
- Repository 负责 SQL 和数据映射。
- Service 只在确实存在跨 repository 编排、事务流程、复杂业务规则时新增。
- 单模块私有类型放在模块目录内，例如 `system.types.ts`。
- 跨模块通用请求解析放 `shared/request-utils.ts`。
- 跨模块通用 repository 辅助函数放 `shared/repository.helpers.ts`。

### 后端权限规则

- 所有需要权限控制的接口必须使用 `@RequirePermission(PERMISSIONS.xxx)`。
- 权限编码从 `@company/constants` 引入，禁止手写字符串。
- 操作日志由全局 `AuditInterceptor` 记录写操作；特殊接口需要手动补日志时使用 `OperationLogService`。

### 管理端规则

- 页面级路由必须配置 `meta.permission`。
- 菜单权限必须与路由权限一致。
- API 文件按业务模块拆分，不继续把业务接口写入 `api/system.ts`。
- 页面内部只写 UI 状态和交互流程，接口调用统一走 `src/api/*`。
- 可复用表格、弹窗、选择器组件达到两个模块复用时，再沉淀到 `components/` 或 `packages/ui`。

## Packages 目录

### api-contract

用于维护前后端共享类型和接口路径。

```text
packages/api-contract/src/
  index.ts
  common.ts
  routes.ts
  auth.ts
  system.ts
  product.ts
  warehouse.ts
  production.ts
  quality.ts
  worker.ts
  inspector.ts
```

规则：

- DTO、列表项、详情项、分页结果类型放这里。
- 接口路径常量放 `routes.ts`。
- 禁止引入前端框架、Nest、数据库类型。

### constants

```text
packages/constants/src/
  index.ts
  permissions.ts
```

规则：

- 权限编码只维护在 `permissions.ts`。
- 前端路由、菜单、后端权限装饰器都从这里引用。
- 禁止在业务代码里手写权限字符串。

### request

```text
packages/request/src/
  index.ts
```

规则：

- 只放 HTTP 客户端通用能力，例如 token 注入、刷新重试、错误转换。
- 不放具体业务接口。

### auth-client

```text
packages/auth-client/src/
  index.ts
```

规则：

- 只封装登录、刷新、退出、当前用户、token 校验等认证流程。
- 不依赖具体页面实现。

### ui

```text
packages/ui/src/
  index.ts
  components/
```

规则：

- 只放跨应用、跨模块复用的通用 UI。
- 单个业务页面专用组件不放这里。
- 示例组件后续应清理或替换为真实通用组件。

### utils

```text
packages/utils/src/
  index.ts
```

规则：

- 只放无框架依赖、无业务状态、无 IO 的纯函数。
- 业务流程函数不放这里。

## 文档目录

```text
docs/
  简易页面划分.md
  业务重梳理，流程重划分（ai补全）.md
  接口路由+权限编码.md

  目录结构规划.md
```

规则：

- 页面、流程、接口、权限、SQL 初始化脚本需要同步维护。
- 权限编码以 `packages/constants/src/permissions.ts` 和 `docs/接口路由+权限编码.md` 为准。
- 数据库初始化脚本以 `docs/init_rbac.sql` 为准。

## 新增模块流程

新增一个业务模块时按以下顺序处理：

1. 在 `docs/接口路由+权限编码.md` 补接口和权限编码。
2. 在 `packages/constants/src/permissions.ts` 补权限常量。
3. 在 `packages/api-contract/src/routes.ts` 补接口路径常量。
4. 在 `packages/api-contract/src/*.ts` 补 DTO 类型。
5. 在 `apps/backend/src/<module>/` 新增 controller / repository / module。
6. 在 `apps/admin-web/src/api/<module>.ts` 新增前端 API 封装。
7. 在 `apps/admin-web/src/views/<module>/` 新增页面。
8. 在 `apps/admin-web/src/router/routes.ts` 补路由和 `meta.permission`。
9. 在 `apps/admin-web/src/views/AdminLayout.vue` 补菜单权限。
10. 在 `docs/init_rbac.sql` 补权限种子。
11. 执行 `pnpm -r build` 和 `pnpm -r test`。

## 当前可接受的临时状态

- `AppModule` 已只负责基础模块装配，后续新增业务模块继续通过 `imports` 接入。
- 管理端系统页面已迁移到 `views/system/`，后续新增业务页面按模块目录创建。
- `packages/ui` 和 `packages/utils` 当前仍有示例性质内容，后续形成真实通用能力时再清理。
