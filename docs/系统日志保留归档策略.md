# 系统日志保留与归档策略（保留优化，暂未实施）

## 保留周期

- 在线表 `operation_logs` 保留最近 180 天，供管理端实时查询。
- 180 天以上日志进入归档库或归档表，至少保留 2 年。
- 登录失败、权限拒绝、用户权限变更、生产报工、工单状态和库存变更日志属于关键日志，不允许直接跳过归档删除。

## 执行方式

- 每日低峰期按主键和时间分批归档，每批不超过 5,000 条。
- 归档成功后再从在线表分批删除，禁止在一个长事务中搬迁全部历史记录。
- 归档任务记录开始时间、结束时间、数量和失败原因，并接入运维告警。
- 删除前校验归档数量和源表数量一致。

## 数据安全

- 归档数据保持只读，数据库账号与在线业务账号分离。
- 归档文件或备份必须加密，并限制系统管理员以外的访问。
- 请求参数继续遵循脱敏规则，不因归档而保存密码、Token、Cookie 或密钥。

## 推荐调度

由部署环境的任务调度器每天执行归档程序。生产环境不依赖 MySQL Event Scheduler，避免不同数据库实例配置不一致。

示例筛选条件：

```sql
SELECT *
FROM operation_logs
WHERE created_at < DATE_SUB(NOW(), INTERVAL 180 DAY)
ORDER BY id
LIMIT 5000;
```

完成外部归档并校验后，再按相同 ID 范围删除在线数据。
