# 生产流程与产品资料维护方案

## 一、添加产品流程，也就是加入产品库

添加产品前，需要先维护基础资料。基础资料包括：生产工序、产品分类、产品信息、产品用料清单、默认工艺路线。

---

## 1、生产工序模块

用于维护后续产品生产时会用到的各个工序。

填写内容：

```text
工序名称
工序编码
工序说明
可选上传技术文件
是否启用
```

说明：

```text
工序编码可以手动填写，也可以按照自定义规则生成。
技术文件可以上传该工序相关的 SOP、作业指导书、检验要求等。
```

举例：

```text
工序名称：装配
工序编码：GX-001
技术文件：装配作业指导书
```

---

## 2、产品分类

用于维护产品的基础分类字段，也用于后续添加产品时自动带出对应的规格参数填写项。

填写内容：

```text
产品属性
产品类型
关联规格参数
是否启用
```

### 产品属性

可自定义，例如：

```text
成品
半成品
原材料
辅料
```

### 产品类型

可自定义，例如：

```text
PCB
滤波器
放大器
环形器
隔离器
连接器
结构件
```

说明：

```text
产品属性、产品类型作为后续添加产品时，《产品信息》表中“产品属性、产品类型”的基础字段。
```

### 关联参数

默认无，可点击新增字段。

后续添加产品时，如果选择了某个产品分类，系统自动补充该分类对应的规格参数填写框。

例如：

环形器可以关联：

```text
频率范围
插入损耗
隔离度
驻波比
功率
接口形式
工作温度
```

PCB 可以关联：

```text
板材
层数
厚度
铜厚
表面处理
```

这样做的好处是：

```text
不同类型的产品填写不同的参数，不需要所有产品都共用一堆无关字段。
```

---

## 3、添加产品

用于建立产品库中的具体产品信息。

填写内容：

```text
产品属性
产品类型
产品型号
产品名称
单位
获取方式
规格参数
默认工艺路线
产品用料清单
是否启用
备注
```

### 产品属性、产品类型

从前面维护的产品分类中选择。

例如：

```text
产品属性：成品
产品类型：环形器
```

---

### 产品型号

填写该产品的型号。

例如：

```text
HMITB60T180G-B2
```

---

### 产品名称

填写该产品的名称。

例如：

```text
宽带微带环形器
```

---

### 单位

例如：

```text
pcs
套
个
件
```

---

### 获取方式

可选：

```text
自制
采购
委外
```

说明：

```text
自制：公司内部生产。
采购：从供应商采购。
委外：交给外部加工厂生产或加工。
```

---

### 规格参数

根据产品类型自动带出需要填写的参数。

例如产品类型选择“环形器”，则自动显示：

```text
频率范围
插入损耗
隔离度
驻波比
功率
接口形式
工作温度
```

---

### 默认工艺路线

这里选择多项之前填写的生产工序，并按照实际生产顺序组成该产品的默认工艺路线。

例如：

```text
装配
↓
调试
↓
检验
↓
包装
```

说明：

```text
产品里的工艺路线是默认模板。
创建工单时，系统默认带出该产品绑定的工艺路线。
如果临时改变，则在工单流程时只修改当前工单的执行工艺路线，不修改产品模板。
```

这一点很重要：

```text
产品模板是标准做法。
工单路线是本次生产实际做法。
```

不能因为某次工单临时调整，就反向改掉产品库里的标准模板。

---

### 产品用料清单

这里不建议在系统里叫 BOM，可以叫：

```text
产品用料清单
```

或者：

```text
这个产品需要用哪些料
```

用于维护生产 1 个该产品，通常需要哪些物料、每种物料用多少。

填写内容：

```text
所需物料
单位用量
是否关键物料
是否需要记录物料批次
损耗率，可选
备注
```

举例：

生产 1 个环形器需要：

```text
腔体：1 个
磁钢：2 个
铁氧体：1 个
连接器：2 个
螺钉：4 个
```

系统用途：

```text
当工单生产数量为 100 个时，系统可以根据产品用料清单自动计算所需物料数量。
```

例如：

```text
腔体：100 个
磁钢：200 个
铁氧体：100 个
连接器：200 个
螺钉：400 个
```

这样后续物料分配时，就不需要每次人工重新计算。

# 二、生产流程

整体流程为：

```text
工单
↓
分配生产任务
↓
产生一个或多个生产任务
↓
生成物料需求
↓
物料分配 / 物料预留
↓
物料出库 / 领料
↓
派工
↓
进入生产
↓
检验
↓
入库 / 返工 / 完工
```

说明：

```text
工艺在添加产品时便完成指派。
如果临时改变，则在工单流程时不按照产品模板做出修改，而是只修改当前工单的执行工艺路线。
```

这里的核心原则是：

```text
生产任务分配和物料分配不要强行绑定成一个动作。
但在页面操作上，可以允许用户选择同时完成。
```

也就是说：

```text
底层逻辑分开。
操作界面可以联动。
```

# 三、填写工单

## 1、工单定义

工单是一次生产计划的正式记录。

它回答的是：

```text
生产什么？
生产多少？
谁负责？
计划什么时候开始？
计划什么时候完成？
按什么工艺路线生产？
```

---

## 2、填写内容

创建工单时填写：

```text
产品
生产数量
生产负责人
计划开工时间
计划完成时间
工单状态
生产工序 / 执行工艺路线
备注
```

---

### 产品

从产品库中选择。

选择产品后，系统自动带出：

```text
产品型号
产品名称
单位
产品类型
产品属性
默认工艺路线
产品用料清单
规格参数
```

---

### 生产数量

填写本次计划生产数量。

例如：

```text
100 pcs
```

---

### 生产负责人

填写该工单的总负责人。

说明：

```text
生产负责人不一定是实际操作员。
生产负责人负责该工单整体推进、协调和跟进。
```

---

### 计划开工时间、计划完成时间

用于后续排产、任务分配和进度跟踪。

---

### 工单状态

工单创建时，建议默认状态为：

```text
草稿
```

点击“下达工单”后，进入：

```text
待分配生产任务
```

不建议在创建工单时让用户随意修改工单状态。

原因是：

```text
工单状态应该由系统根据实际动作自动流转。
如果允许人工随便改，后续追溯时很难判断真实过程。
```

---

## 3、工单状态建议

工单状态可以设计为：

```text
草稿
待分配生产任务
生产任务部分分配
生产任务分配完成
待物料分配
物料部分分配
物料已齐套
待派工
生产中
已完工
已关闭
已取消
```

说明：

```text
草稿：工单还没正式下达。
待分配生产任务：工单已经下达，但还没有拆分任务。
生产任务部分分配：只分配了部分生产数量。
生产任务分配完成：工单数量已经全部分配到一个或多个生产任务中。
待物料分配：任务已分配，但还没有处理物料。
物料部分分配：部分物料已经分配或预留，但还没完全齐套。
物料已齐套：生产所需物料已经准备完成。
待派工：物料已经准备好，但所有任务的第一道工序都还未开始生产。
生产中：至少有一个任务的第一道工序已开始生产。
已完工：工单生产完成。
已关闭：工单流程结束，不再继续操作。
已取消：工单取消。
```

---

## 4、生产工序 / 执行工艺路线

工单创建时，系统按照产品绑定的工序自动填充模板。

也可以选择不使用绑定模板，在当前工单中做出修改。

说明：

```text
产品里的工艺路线是默认模板。
工单里的工艺路线是本次实际执行路线。
```

如果临时改变：

```text
只修改当前工单。
不修改产品模板。
不影响以后其他工单。
```

这样可以保证：

```text
标准资料稳定。
实际生产灵活。
历史记录真实。
```

# 四、分配生产任务

## 1、分配生产任务的作用

分配生产任务是把一个工单拆成一个或多个可执行任务。

例如：

```text
工单生产数量：100 pcs
```

可以分配为：

```text
任务 1：40 pcs
任务 2：60 pcs
```

也可以分配为：

```text
任务 1：100 pcs
```

---

## 2、分配生产任务填写内容

填写：

```text
分配量
任务负责人 / 班组 / 操作员
计划开始时间
计划完成时间
生产批次号
是否生成物料需求
是否立即分配物料
备注
```

说明：

```text
任务状态、物料状态不由用户手动填写，而是由系统根据后续流程自动计算。
派工状态不在这里设置，因为派工是按工序独立进行的，详见派工流程章节。
```

---

### 分配量

填写本次分配给该任务的生产数量。

说明：

```text
如果按照该工单完全分配，则工单进入“生产任务分配完成”状态。
如果多个任务需要总和所有任务完全分配，才进入“生产任务分配完成”状态。
```

例如：

```text
工单数量：100 pcs
任务 1：40 pcs
```

此时工单状态为：

```text
生产任务部分分配
```

继续分配：

```text
任务 2：60 pcs
```

此时任务总量为：

```text
40 + 60 = 100 pcs
```

工单状态变为：

```text
生产任务分配完成
```

---

### 任务负责人 / 班组 / 操作员

用于明确这个任务由谁负责或执行。

可以根据实际管理方式选择：

```text
只分配到负责人
只分配到班组
直接分配到操作员
```

轻量版本建议先支持：

```text
任务负责人
```

后续再扩展到：

```text
班组
操作员
多人协作
```

---

### 计划开始时间、计划完成时间

用于任务排期。

可以默认继承工单计划时间，也可以在任务中单独调整。

---

### 生产批次号

建议每个生产任务都生成一个生产批次号。

原因是后续追溯需要知道：

```text
这个任务用了哪些料？
谁做的？
经过哪些工序？
检测结果是什么？
有没有返工？
最后入库了多少？
```

生产批次号可以系统自动生成，也可以手动填写。

建议系统自动生成，规则例如：

```text
SCPC-年月日-流水号
```

---

### 是否生成物料需求

建议默认选择：

```text
是
```

含义是：

```text
系统根据产品用料清单和任务数量，自动计算这个任务需要哪些物料、需要多少。
```

例如任务数量为 40 pcs，产品用料清单中每个产品需要 2 个连接器，则系统自动生成：

```text
连接器：80 个
```

---

### 是否立即分配物料

这里可以给用户选择：

```text
否，后续单独分配
是，现在同时分配
```

建议默认：

```text
否，后续单独分配
```

原因是：

```text
任务分配关注的是生产安排。
物料分配关注的是库存和物料批次。
两者不要强耦合。
```

但可以提供一个便捷操作：

```text
分配任务并生成物料需求
分配任务并立即分配物料
```

这样既不破坏系统结构，也能让操作更方便。

# 五、任务分配和物料分配的关系

## 1、结论

```text
任务分配和物料分配不应该强绑定。
```

正确方式是：

```text
任务分配完成后，系统自动生成物料需求。
物料可以后续单独分配。
也可以在分配任务时选择同时分配。
```

也就是：

```text
流程上分开。
操作上可以合并。
状态上必须能追踪。
```

---

## 2、为什么不能强绑定？

因为实际生产中会出现这些情况：

```text
任务已经分配，但仓库暂时缺料。
任务已经分配，但还没确定用哪个物料批次。
任务数量临时调整，物料需求也要跟着调整。
物料已经预留，但任务取消，需要释放物料。
物料已经出库，但生产过程中有损耗或退料。
```

如果任务分配和物料分配强行绑死，后续会很难处理。

---

## 3、推荐的中间状态

任务分配完成后，不要直接进入生产。

建议进入：

```text
待物料分配
```

或者：

```text
待备料
```

物料处理完成后，再进入：

```text
物料已齐套
```

然后才允许：

```text
派工
```

# 六、物料分配流程

## 1、物料需求生成

当生产任务创建后，系统根据：

```text
产品用料清单
任务数量
```

自动生成这个任务需要的物料。

生成内容：

```text
生产任务
所需物料
需求数量
已分配数量
未分配数量
物料状态
是否关键物料
是否需要记录物料批次
备注
```

---

## 2、物料分配 / 物料预留

物料分配时，需要从仓库现有物料批次中选择。

填写内容：

```text
生产任务
所需物料
需求数量
分配数量
物料批次
仓库位置
分配人
分配时间
备注
```

说明：

```text
物料分配可以理解为：先把这批料给这个任务占住。
```

这一步不一定等于出库。

---

## 3、物料出库 / 领料

当生产真的要开始前，仓库再进行出库或领料确认。

填写内容：

```text
生产任务
物料名称
物料批次
出库数量
领料人
出库人
出库时间
备注
```

说明：

```text
物料分配：先占住。
物料出库：真的从仓库发出。
```

建议不要把这两个动作完全混在一起。

轻量版本可以先做成一个动作，但状态上最好保留区别。

---

## 4、物料状态

建议任务中单独保留一个物料状态：

```text
未生成需求
待物料分配
物料部分分配
物料已分配
物料已齐套
物料已出库
缺料
已退料
```

说明：

```text
未生成需求：任务还没有根据产品用料清单生成所需物料。
待物料分配：已经知道需要哪些料，但还没分配。
物料部分分配：只分配了一部分。
物料已分配：物料已经全部分配或预留。
物料已齐套：生产所需物料已经准备齐全。
物料已出库：物料已经从仓库发出。
缺料：库存不足或无法满足生产。
已退料：生产后有物料退回仓库。
```

---

# 七、派工流程

## 1、派工条件

建议派工前至少满足：

```text
生产任务已创建
任务负责人或操作员已确定
物料状态为物料已齐套，或物料已出库
工艺路线已确认
```

如果物料缺料，则不建议允许派工，或者派工时给出明显提醒。

---

## 2、派工填写内容

```text
生产任务
派工对象
派工时间
计划开始时间
计划完成时间
当前工序
派工状态
备注
```

派工对象可以是：

```text
班组
操作员
检测人员
```

---

### 默认派工对象

为提高派工效率，建议为每个工序预设默认派工对象。

```text
默认派工对象从工艺路线模板或系统配置中预设。
每个工序可绑定一个默认操作员或班组。
派工时系统自动填入默认对象，并在界面上标记「(默认)」。
用户可直接确认派工，也可手动修改为其他人。
手动修改后不再标记「(默认)」，表示本次派工使用了非默认对象。
```

页面操作上提供：

```text
一键按默认派工：将当前批次下所有「未派工」工序按默认对象完成派工。
改派：修改已派工工序的派工对象。
清除派工：取消未开始生产的工序派工。
```

这样既保留了按工序精细派工的灵活性，又减少了重复选择人员的操作成本。

---

## 3、派工状态

建议设置：

```text
未派工
已派工
已接收
生产中
已完成
已暂停
已取消
```

说明：

```text
未派工：任务还没安排给具体执行人。
已派工：任务已经安排。
已接收：执行人确认收到任务。
生产中：任务已经开始生产。
已完成：任务完成。
已暂停：任务暂时停止。
已取消：任务取消。
```

---

## 4、派工与任务/工单状态的映射关系

派工是按「工序」独立进行的，每个工序有自己的派工记录和派工状态。生产任务状态和工单状态是对所有工序状态的聚合结果。

### 举例说明

假设一个生产任务有 4 道工序：装配 → 调试 → 检验 → 包装

**场景一：物料已齐套，所有工序都未派工**

```text
工序派工状态：装配(未派工) → 调试(未派工) → 检验(未派工) → 包装(未派工)
生产任务状态：待派工
工单状态（假设仅此一个任务）：待派工
```

**场景二：装配已派工给张三，但还没开始生产**

```text
工序派工状态：装配(已派工/张三) → 调试(未派工) → 检验(未派工) → 包装(未派工)
生产任务状态：已派工（第一道工序已安排人，等待开工）
工单状态：待派工（还有任务未开始生产）
```

**场景三：装配已开始生产**

```text
工序派工状态：装配(生产中/张三) → 调试(未派工) → 检验(未派工) → 包装(未派工)
生产任务状态：生产中
工单状态：生产中
```

**场景四：装配已完成，调试已派工给李四**

```text
工序派工状态：装配(已完成) → 调试(已派工/李四) → 检验(未派工) → 包装(未派工)
生产任务状态：生产中
工单状态：生产中
```

**场景五：所有工序都已完成**

```text
工序派工状态：装配(已完成) → 调试(已完成) → 检验(已完成) → 包装(已完成)
生产任务状态：已完成
工单状态：已完工
```

### 映射规则总结

| 条件 | 生产任务状态 | 工单状态 |
|------|-------------|---------|
| 所有工序都**未派工** | 待派工 | 待派工 |
| 第一道工序**已派工**，但所有工序都未开始生产 | 已派工 | 待派工 |
| 至少一道工序**已开始生产** | 生产中 | 生产中 |
| 所有工序**已完成** | 已完成 | — |
| 该工单下所有任务都已完成 | — | 已完工 |
| 任务/工单被暂停 | 已暂停 | — |
| 任务/工单被取消 | 已取消 | 已取消 |

### 派工管理页面展示

派工管理页面以「生产批次号」为区块单位展示，每个区块包含该批次的所有工序：

```text
┌──────────────────────────────────────────────────────────────────────────────────┐
│ 生产批次号：SCPC-20260609-001         任务状态：🔵 待派工                       │
│ 工单：ORD-20260609-001   产品：宽带微带环形器   数量：40 pcs                    │
│                                                                                  │
│ 工序 │ 默认派工对象 │ 派工对象       │ 工序派工状态 │ 操作                      │
│──────┼─────────────┼────────────────┼─────────────┼───────────────────────────│
│ 装配 │ 张三        │ 张三 (默认)     │ 已派工       │ 改派                      │
│ 调试 │ 李四        │ 李四 (默认)     │ 已派工       │ 改派                      │
│ 检验 │ 王五        │ —              │ 未派工       │ [派工]                    │
│ 包装 │ 赵六        │ —              │ 未派工       │ [派工]                    │
│                                                                                  │
│                               [一键按默认派工] [清除全部派工]                    │
└──────────────────────────────────────────────────────────────────────────────────┘
```

**默认派工对象**：从工艺路线模板或系统配置中预设，首次打开页面时自动填入并标记「(默认)」。

**一键按默认派工**：点击后将当前批次下所有「未派工」工序的派工对象设置为默认对象，工序派工状态变更为「已派工」。

**改派与清除**：点击「改派」手动修改派工对象，修改后不再标记「(默认)」。「清除全部派工」取消未开始生产的工序派工。

**任务级派工状态标签**（区块顶部展示）

| 标签 | 含义 | 后续操作指引 |
|-----|------|------------|
| 🔵 待派工 | 第一道工序还未派工 | 需要点击"派工"安排人员 |
| 🟡 已派工 | 第一道工序已派工，等待开工 | 无需再派工，等待执行人开始生产 |
| 🟢 生产中 | 已有工序开始生产 | 关注生产进度，无需处理派工 |

这样用户在派工管理页面一眼就能看出：
- **哪些任务还需要派工**（🔵 待派工）
- **哪些任务已经派了但还没开工**（🟡 已派工）
- **哪些任务已经在生产了**（🟢 生产中）

每个工序的派工仍然是独立操作，修改某一工序的派工对象不会影响其他工序。

# 八、进入生产

## 1、生产开始条件

任务进入生产前，建议满足：

```text
工单已下达
生产任务已分配
物料已齐套或已出库
当前工序已派工
当前工序明确
```

说明：

```text
"当前工序已派工"指该任务当前要执行的工序已经派给了具体操作员。
不需要所有工序都派工才能开始生产，后续工序可以在前一工序完成时再派工。
```

---

## 2、生产执行记录（报工）

生产执行记录（简称报工）是记录每道工序实际生产结果的核心数据。报工由生产负责人或管理端人员填报，也可以在员工端由操作员自行填报后由负责人审核。

### 报工流程

```text
开工 → 生产执行 → 完工报工 → 审核确认（可选）
```

### 开工

工序开始生产时，记录开工信息：

```text
生产批次号
当前工序
操作员
开工时间
设备/工位（可选）
备注
```

说明：

```text
开工后该工序的派工状态自动变为"生产中"。
开工时间作为后续计算工时和排产分析的依据。
```

### 完工报工

工序生产完成后，填报完工数据：

```text
生产批次号
当前工序
操作员
开工时间（自动带入）
完工时间
完成数量
合格数量
不合格数量
不合格原因
异常说明
上传文件（检验图片、记录表等）
报工时间
报工人
备注
```

说明：

```text
完成数量 = 合格数量 + 不合格数量。
不合格原因建议用下拉选择（如：尺寸超差、外观不良、性能不达标等），也可手动填写。
上传文件支持图片、PDF等格式，用于附上检测记录或异常照片。
开工时间和操作员从开工记录中自动带入，无需重复填写。
```

### 报工状态（每道工序独立）

```text
未开工：已派工但尚未开始生产。
已开工：已记录开工时间，生产中。
已报工：已填报完工数据，待确认。
已确认：负责人已审核确认，数据锁定。
已异常：生产过程中出现异常，暂停或中断。
```

---

## 3、生产报工的管理端操作

管理端（生产负责人）可以直接在报工页面上进行以下操作：

```text
开工：点击开工按钮，记录该工序的开始时间。
完工：弹出报工表单，填报完工数据。
开工并报工：一步完成开工和完工，适用于一道工序一次做完的情况。
查看：查看已确认的报工记录详情。
```

### 报工页面设计

报工页面与派工管理结构一致，按「生产批次号」分块展示：

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│ 生产批次号：SCPC-20260609-002         任务状态：🟢 生产中                  │
│ 工单：ORD-20260609-001   产品：宽带微带环形器   数量：60 pcs               │
│                                                                             │
│ 工序 │ 操作员 │ 开工时间     │ 完工时间  │ 合格/总  │ 报工状态 │ 操作     │
│──────┼───────┼─────────────┼──────────┼─────────┼─────────┼──────────│
│ 装配 │ 张三  │ 06/10 08:00 │ 06/10 10:30 │ 38/40 │ 已确认  │ [查看]   │
│ 调试 │ 李四  │ 06/10 11:00 │ —        │ —/—     │ 已开工  │ [完工]   │
│ 检验 │ 王五  │ —           │ —        │ —/—     │ 未开工  │ [开工]   │
│ 包装 │ 赵六  │ —           │ —        │ —/—     │ 未开工  │ [开工]   │
│                                                                             │
│                           [开工并报工] [批量报工]                            │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 报工表单内容

点击「完工」或「开工并报工」后弹出报工表单：

```text
生产批次号（自动带入）
工序（自动带入）
操作员（从派工数据自动带入）
开工时间（自动带入，可追溯）
完工时间（默认当前时间，可修改）
完成数量    —— 本次完成的总数量
合格数量    —— 合格品数量
不合格数量  —— 不合格品数量
不合格原因  —— 下拉选择：尺寸超差 / 外观不良 / 性能不达标 / 其他
异常说明    —— 文本描述
上传文件    —— 检测记录、异常照片等
备注        —— 其他说明
报工人      —— 当前操作员自动带入
```

### 与其他模块的衔接

```text
报工数据 → 自动更新工序派工状态为"已完成"
报工数据 → 任务的合格数量累加，不合格数量累加
报工数据 → 作为检验记录和追溯的基础数据
报工数据 → 计算工时 = 完工时间 - 开工时间
```

```text

待派工

生产中

```

说明：

```text
这里恢复了"已派工"状态，但含义与之前不同——它不表示"所有工序都已派工"，而是表示"第一道工序已完成派工"。
派工是按工序独立进行的，但第一道工序的派工状态决定了任务是否具备了开工条件。

待处理：任务刚创建，尚未处理物料。
待物料分配：物料需求已生成，等待分配物料。
待派工：物料已齐套，但第一道工序**还未派工**（所有工序都是未派工状态）。
已派工：物料已齐套，第一道工序**已派工**，但尚未开始生产（后续工序可能已派工也可能未派工）。
生产中：至少有一道工序已经开始生产。
已完成：所有工序都已生产完成。
已暂停：任务暂时停止。
已取消：任务取消。
```

# 十五、你的关键问题的最终结论

## 1、分配任务时，是否应该同时把物料也分配好？

结论：

```text
不应该强制同时完成。
```

正确做法：

```text
分配生产任务后，系统自动生成物料需求。
物料分配可以后续单独完成。
也可以在分配任务时选择“同时分配物料”。
```

也就是：

```text
默认分开。
允许联动。
不要强耦合。
```

---

## 2、是否需要一个中间状态？

结论：

```text
需要。
```

建议增加：

```text
待物料分配
物料部分分配
物料已齐套
```

这样可以清楚区分：

```text
任务已经分配了，但料还没准备好。
```

而不是任务一分配就默认可以生产。

---

## 3、分配生产任务目前只有“分配量”字段，够不够？

结论：

```text
不够。
```

至少应增加：

```text
任务负责人 / 班组 / 操作员
计划开始时间
计划完成时间
生产批次号
是否生成物料需求
是否立即分配物料
备注
```

注意：

```text
任务状态、物料状态、派工状态不由用户手动填写，由系统自动计算。
```

如果只保留“分配量”，后续只能知道分了多少，无法知道：

```text
谁做
什么时候做
料有没有准备好
是否已经派工
是否已经开始生产
是否完成
异常卡在哪里
```

# 十六、最终一句话版本

这套流程应该设计成：

```text
产品资料先定义“怎么做”和“用哪些料”。
工单负责确定“这次生产什么、生产多少”。
生产任务负责确定“拆给谁、做多少”。
物料分配负责确定“用哪些库存批次的料”。
派工负责确定“谁正式开始执行”。
生产、检验、返工、入库负责形成完整追溯。
```

最重要的原则是：

```text
任务分配和物料分配不要绑死。
但可以在页面上提供一键联动。
```

这样系统不会一开始就很重，但骨架是正的。后面无论加缺料提醒、批次追溯、返工管理、检测文件、出货追溯，都能顺着这条线继续长出来。
