| `updated_at` | 需求更新时间 |

### 当前状态值设计

    shortage
    issued
    partial_issued
    allocated
    partial_allocated
    unallocated

### 当前逻辑问题

当前状态判断包含类似以下逻辑：

    WHEN reserved_quantity < plan_quantity THEN 'shortage'
    ...
    WHEN reserved_quantity > 0 THEN 'partial_allocated'

只要出现部分预留，就已经满足第一条 `shortage`，因此 `partial_allocated` 基本不会出现。

### 建议的状态判断顺序

    净领料达到需求  -> issued
    存在部分净领料  -> partial_issued
    预留达到需求    -> allocated
    存在部分预留    -> partial_allocated
    完全未预留      -> unallocated

“缺料”不建议与业务阶段混在同一个字段中，可以另外增加：

| 建议字段 | 含义 |
|---|---|
| `is_shortage` | 是否缺料 |
| `shortage_quantity` | 缺料数量 |

此外，`usage_id = requirement.id` 的命名容易产生误导，建议删除该字段，或者改成含义明确的兼容字段名。

### 当前用途

该视图是库存口径的核心视图，已经被以下模块使用：

- 物料分配
- 产品查询
- 库存
- 盘点

### 库存计算口径说明

`material_batches.quantity` 在领料时已经减少，在退料时已经增加。

因此，以下计算口径是合理的：

    available_quantity
    = 当前库存
    − 仍被预留但尚未领用的数量

`used_quantity` 是历史净领用统计，不应再次从库存数量中扣除。

### 当前问题

对于“预留数量小于净领用数量”的异常情况，使用以下处理会隐藏数据异常：

    GREATEST(..., 0)

### 建议补充字段

| 建议字段 | 含义 |
|---|---|
| `reservation_overissued_quantity` | 超出有效预留数量的净领用数量 |
| `has_reservation_exception` | 是否存在预留与领用数据异常 |
| `is_available` | 当前物料库存批次是否可用 |

| `remark` | 操作备注 |

### 当前问题

`operation_type_text` 已出现明确乱码。例如，“预留”“取消预留”“领料”“退料”等 SQL 文本被错误编码。

必须先将这些文本恢复为正常的 UTF-8 中文。

### 建议补充字段

| 建议字段 | 含义 |
|---|---|
| `requirement_id` | 对应的物料需求 ID |
| `product_material_id` | 对应的产品 BOM 关系 ID |
| `signed_quantity` | 按操作方向表示的正负变化数量 |

### `signed_quantity` 建议口径

    reserve    -> 正预留
    unreserve  -> 负预留
    issue      -> 负库存流向 / 正领用量
    return     -> 正库存流向 / 负领用量

其中，`issue` 和 `return` 的正负值取决于该字段表达的是“库存变化”还是“领用变化”，容易产生歧义。

因此，建议分别提供以下字段：

| 建议字段 | 含义 |
|---|---|
| `reservation_change_quantity` | 预留数量变化；预留为正，取消预留为负 |
| `stock_change_quantity` | 库存数量变化；领料为负，退料为正 |

相比使用一个含义不明确的 `signed_quantity`，拆分为两个变化字段更加安全，也更方便查询、统计和展示。

### 建议计算口径

    is_material_ready =
      没有物料需求
      或所有有效物料需求均达到预留要求

### 收益

当前生产任务列表中，同类 `COUNT`、`SUM(CASE...)` 和相关子查询至少重复了数次。

该视图是减少生产任务 SQL 体积最明显的一项，同时可以统一列表和详情页面的进度统计口径。

| `shortage` | 盘亏 |
