# 统一库存方案迁移清单

本文档用于指导本分支从旧仓储物料方案迁移到 `docs/newSqlDesign.md` 中的统一库存对象方案。迁移目标不是一次性推翻全部业务代码，而是按可验证的小步逐步完成，确保前后端权限、路由、接口契约、数据库和页面展示始终保持一致。

## 一、迁移原则

1. 方案二以 `docs/newSqlDesign.md` 为数据库设计基准。
2. 旧 `material_batches`、`batch_material_usages`、`material_batch`、`material_demand`、`material_allocation` 不再作为后续开发依据。
3. 库存对象统一使用 `products` 表（融合原 `item_info`），库存批次统一使用 `item_batch`，库存数量统一来自 `inventory_transaction` 和视图汇总。
4. 生产批次 `production_batches` 与库存批次 `item_batch` 必须分离，不允许把生产批次 ID 当库存批次 ID 使用。
5. 分配只表达预留占用，不生成库存流水；入库、出库、退料、报废、盘点调整必须生成库存流水。
6. 前后端共享类型、接口路径、权限编码必须先在 `packages/api-contract` 和 `packages/constants` 中统一，再进入业务实现。
7. 从主分支复用前端代码时，只按功能点 diff 后提取可复用 UI、组件、表格交互、弹窗结构和消息反馈，不直接整块合并旧仓储数据流。
