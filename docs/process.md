一、目前任务归属规则是：
工序负责人设置为“检测人员”，但 需专检/need_inspection = 0：仍属于普通生产工序，显示在该人员的“员工任务”中。
工序设置 需专检/need_inspection = 1：无论负责人是谁，都只显示在“检测任务”中，不会出现在员工任务里。
检测任务提交结果后：系统同时完成该工序（可进入下一工序）并生成正式检验记录。

编码规则

二、工单与任务批次业务规则
1. 工单创建任务批次
当前允许以下工单创建任务批次：
草稿
已下达
生产中
不允许以下工单创建任务：
已完成
已关闭
已取消
补充规则：
工单必须有剩余可分配数量。
任务计划数量不能超过工单剩余数量。
草稿工单首次创建任务后自动变为“已下达”。
一个工单可以拆分成多个任务批次。
2. 任务工序初始化
创建任务时，根据所选工艺路线生成批次工序记录。
每道工序会固化：
工序顺序
默认负责人
默认参考文件
最终生效负责人
最终生效参考文件
重要参数定义
生效规则：
生效负责人 = 实际负责人 ?? 默认负责人
生效参考文件 = 实际文件 ?? 默认文件
确认派工时，即使没有人工修改，也会把默认负责人和默认文件写入批次工序，避免其他模块再次查询可能变化的路线配置。
3. 生成物料需求
任务开始前必须生成物料需求。
物料需求根据以下数据计算：
需求数量 = 单位用量 × 任务计划数量
物料需求与库存操作分开：
需求记录计划用量。
预留记录具体使用哪个库存批次。
出库记录实际领料数量。
退料记录实际退回数量。
4. 任务派工
派工需要确定每道工序最终使用的：
负责人
参考文件
用户可以：
直接采用默认配置。
选择其他已有文件。
上传实际参考文件。
指定其他实际负责人。
默认配置后续发生变化，不影响已经派工的任务批次。
5. 任务开始条件
任务开始前，后端强制校验：
任务状态允许开始。
已生成物料需求。
已生成工序记录。
每道工序都有生效负责人。
物料分配目前不是强制开始条件：
存在未分配物料：警告。
存在部分分配物料：警告。
关键物料未完全分配：警告。
用户确认后仍可开始任务。
6. 物料预留与出库
核心库存口径：
预留：不扣库存
取消预留：不改库存
出库：扣减库存
退料：增加库存
物料出库必须满足：
任务状态为“生产中”。
已预留具体物料库存批次。
出库数量不超过剩余预留数量。
出库数量不超过当前库存数量。
因此，没有完成物料预留时，即使任务已经开始，也无法领料出库。
7. 工序执行
工序执行遵循工艺路线顺序：
前序工序完成或异常结束后，后序工序才能开始。
需检工序必须检验放行，后续工序才能继续。
完成或异常报工时，必须填写配置的重要参数。
产出、返工和异常数量必须符合工序数量流转规则。
8. 任务完成
任务完成前必须满足：
不存在待开始或执行中的工序。
所有需检工序已经检验放行。
任务完成后：
任务状态变为“已完成”。
不再允许派工或修改任务配置。
不再允许物料出库。
9. 当前完整流程
创建工单
→ 创建任务批次
→ 生成物料需求
→ 派工
→ 分配并预留物料
→ 开始任务
→ 物料出库
→ 工序报工
→ 必要的工序检验
→ 完成任务
