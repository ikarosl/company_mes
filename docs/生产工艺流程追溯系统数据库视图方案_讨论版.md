# 生产工艺流程追溯系统数据库视图方案（讨论版）

> 版本：讨论版  
> 目的：用于当前系统开发讨论，明确一期需要哪些数据库视图、每个视图服务哪些页面、解决哪些重复联表和重复计算问题。  
> 适用范围：一期轻量生产过程追溯系统。视图只用于查询展示和汇总计算，不承担新增、编辑、删除、状态流转等写入逻辑。

> 2026-06-24 实施状态：`v_batch_material_allocation`、`v_material_batch_available`、`v_production_batch_overview` 已落地。当前 `batch_material_usages` 没有 `operation_type` 字段，因此一期按 `reserved_quantity`、`used_quantity`、`status` 计算，不在视图中虚构领料和退料流水。

---

## 一、视图设计原则

一期系统不建议一次性建立过多视图。视图应优先服务高频页面和复杂查询场景，避免为了“完整”而增加维护成本。

### 1.1 什么情况适合建视图

满足以下条件时，建议建数据库视图：

1. 多个页面会反复使用同一类查询结果。
2. 查询需要频繁关联三张以上业务表。
3. 查询中存在固定计算字段，例如需求数量、已预留数量、已使用数量、未满足数量、可用数量。
4. 字段口径需要统一，避免前端、后端各算各的。
5. 查询主要用于列表、详情、页签、弹窗、追溯展示，不用于写入。

### 1.2 什么情况不建议建视图

以下场景暂不建议建视图：

1. 单表或两三张表即可完成的普通列表查询。
2. 只在一个页面偶尔使用的查询。
3. 需要复杂权限判断、按钮控制、状态流转的逻辑。
4. 需要事务保证的写入逻辑，例如物料分配、报工提交、检验提交、返工关闭。

### 1.3 视图和接口的边界

数据库视图负责：

```text
查询展示
联表铺平
汇总计算
状态辅助展示
追溯信息聚合
```

后端接口负责：

```text
新增
编辑
删除
状态流转
权限校验
业务规则校验
事务控制
日志记录
```

一句话原则：

```text
视图负责“看清楚”，接口负责“管得住”。
```

## 三、核心视图设计

## 3.1 `v_batch_material_allocation` 生产批次物料分配视图

### 3.1.1 用途

用于“物料分配”页面，也可用于生产批次详情中的“物料需求”页签。

它回答的问题是：

```text
某个生产批次需要哪些物料？
每种物料需要多少？
已经预留多少？
已经领用多少？
还差多少？
物料状态是什么？
```

这是当前最有价值的视图之一，可以减少后端大量重复 join 和重复计算。

### 3.1.2 行粒度

建议行粒度为：

```text
一个生产批次 + 一个产品用料清单项
```

也就是：

```text
batch_id + product_material_id
```

不要把行粒度直接落到具体物料批号，否则一个物料需求如果由多个物料批次分摊，页面会被拆成多行，不利于物料分配页面展示。

### 3.1.3 主要关联表

```text
production_batches
work_orders
products              -- 成品/生产产品
product_materials
products              -- 物料产品，自关联
batch_material_usages
material_batches
```

### 3.1.4 建议字段

| 字段名 | 说明 |
|---|---|
| `batch_id` | 生产批次 ID |
| `batch_no` | 生产批次号 |
| `work_order_id` | 工单 ID |
| `order_no` | 工单号 |
| `product_id` | 生产产品 ID |
| `product_code` | 生产产品编码 |
| `product_model` | 生产产品型号 |
| `product_name` | 生产产品名称 |
| `planned_quantity` | 批次计划数量 |
| `product_material_id` | 产品用料清单 ID |
| `material_product_id` | 物料产品 ID |
| `material_code` | 物料编码 |
| `material_model` | 物料型号 |
| `material_name` | 物料名称 |
| `quantity_per_unit` | 单位用量 |
| `required_quantity` | 需求数量 |
| `reserved_quantity` | 已预留数量 |
| `issued_quantity` | 已领料/已使用数量 |
| `returned_quantity` | 已退料数量 |
| `net_used_quantity` | 净使用数量 |
| `unfulfilled_quantity` | 未满足数量 |
| `unit` | 单位 |
| `is_key_material` | 是否关键物料 |
| `need_batch_record` | 是否需要记录批号 |
| `allocated_material_batch_count` | 已分配物料批次数量 |
| `allocated_material_batch_nos` | 已分配物料批号列表，可选 |
| `material_status` | 物料状态 |

### 3.1.5 计算字段建议

当前一期实际口径：

```text
required_quantity = batch_material_usages.plan_quantity
current_bom_required_quantity = product_materials.quantity_per_unit × production_batches.planned_quantity
unfulfilled_quantity = MAX(required_quantity - reserved_quantity, 0)
```

其中 `required_quantity` 是生成需求时保存的业务快照，`current_bom_required_quantity` 用于核对当前 BOM。修改 BOM 时，系统只同步尚未分配、未预留、未使用的需求；已经进入分配或领用的数据保持历史口径。

以下 `operation_type` 计算方式作为后续扩展方案保留，当前一期尚未启用：

```text
required_quantity = product_materials.quantity_per_unit × production_batches.planned_quantity
```

```text
reserved_quantity = SUM(batch_material_usages.reserved_quantity WHERE operation_type = 'reserve')
```

```text
issued_quantity = SUM(batch_material_usages.used_quantity WHERE operation_type = 'issue')
```

```text
returned_quantity = SUM(batch_material_usages.used_quantity WHERE operation_type = 'return')
```

```text
net_used_quantity = issued_quantity - returned_quantity
```

```text
unfulfilled_quantity = required_quantity - reserved_quantity
```

物料状态建议：

| 判断条件 | 状态值 | 页面文案 |
|---|---|---|
| `reserved_quantity = 0` | `unallocated` | 未分配 |
| `reserved_quantity > 0 AND reserved_quantity < required_quantity` | `partial_allocated` | 部分分配 |
| `reserved_quantity >= required_quantity AND issued_quantity = 0` | `allocated` | 已分配 |
| `issued_quantity > 0 AND issued_quantity < required_quantity` | `partial_issued` | 部分领料 |
| `issued_quantity >= required_quantity` | `issued` | 已领料 |
| `unfulfilled_quantity > 0` | `shortage` | 缺料 |

### 3.1.6 使用页面

| 页面 | 使用方式 |
|---|---|
| 物料分配页面 | 主表格数据源 |
| 生产批次详情 | “物料需求”页签 |
| 物料与派工页面 | 物料需求/分配区域 |
| 生产开工前检查 | 判断关键物料是否缺料 |
| 仓储备料页面 | 按生产批次查看需备料情况 |

### 3.1.7 注意事项

1. 该视图只负责展示和计算，不负责写入。
2. 分配物料、确认领料、登记退料仍写入 `batch_material_usages`。
3. 如果 `batch_material_usages.used_quantity` 在 `return` 场景中不表示退料数量，则需要新增退料数量字段或统一字段口径。

## 3.2 `v_material_batch_available` 物料批次可用库存视图

### 3.2.1 用途

用于分配物料批次时，下拉框或弹窗显示可用物料批次。

它回答的问题是：

```text
某种物料有哪些批号？
每个物料批号还有多少可用？
哪些批号已经被预留？
哪些批号已经被使用？
```

该视图可保证库存页面和物料分配页面的“可用量”口径一致。

### 3.2.2 行粒度

建议行粒度为：

```text
一个物料批次
```

也就是：

```text
material_batch_id
```

### 3.2.3 主要关联表

```text
material_batches
products
batch_material_usages
```

### 3.2.4 建议字段

| 字段名 | 说明 |
|---|---|
| `material_batch_id` | 物料批次 ID |
| `material_batch_no` | 物料批号 |
| `material_product_id` | 物料产品 ID |
| `material_code` | 物料编码 |
| `material_model` | 物料型号 |
| `material_name` | 物料名称 |
| `supplier_name` | 供应商 |
| `protocol_code` | 技术协议编码 |
| `received_date` | 入库日期 |
| `stock_quantity` | 台账数量 |
| `reserved_quantity` | 已预留数量 |
| `issued_quantity` | 已使用/已领料数量 |
| `returned_quantity` | 已退料数量 |
| `reserved_not_issued_quantity` | 已预留未使用数量 |
| `available_quantity` | 可用数量 |
| `material_batch_status` | 物料批次状态 |

### 3.2.5 计算字段建议

当前一期实际口径：

```text
reserved_not_used_quantity = SUM(MAX(reserved_quantity - used_quantity, 0))
available_quantity = material_batches.quantity - reserved_not_used_quantity
```

状态为 `cancelled` 的使用记录不计入有效预留。分配接口仍会在写入前重新校验可用量。

如果 `material_batches.quantity` 表示当前台账数量，并且不会在每次领料时立即扣减，则建议：

```text
reserved_not_issued_quantity = reserved_quantity - issued_quantity
```

```text
available_quantity = stock_quantity - reserved_not_issued_quantity
```

如果 `material_batches.quantity` 已经会随着领料被扣减，则建议：

```text
available_quantity = material_batches.quantity - reserved_not_issued_quantity
```

实际公式需要在开发前确认 `material_batches.quantity` 的口径。

### 3.2.6 使用页面

| 页面 | 使用方式 |
|---|---|
| 物料分配弹窗 | 按物料产品筛选可用物料批次 |
| 物料批次台账 | 展示参考可用数量 |
| 仓储库存查询 | 查看每个物料批号的可用情况 |
| 生产批次物料分配 | 选择具体物料批号时调用 |

### 3.2.7 注意事项

1. 该视图中的可用数量属于轻量生产追溯系统的参考值，不作为财务库存依据。
2. 严格库存扣减、库存锁定、成本核算不应由该视图承担。
3. 分配时后端仍需校验可用量，不能只依赖前端展示结果。

### 3.3.6 注意事项

1. 该视图建议先保持轻量，不要把物料状态、检验状态、返工状态、发货状态全部塞进去。
2. 如果后续批次列表确实需要这些状态，可再扩展视图或由后端聚合。
3. 避免把该视图做成“超级大视图”。

## 3.5 `v_material_batch_distribution` 物料批号去向视图

### 3.5.1 用途

用于查看某个物料批号分配、领用或退料到了哪些生产批次。

它回答的问题是：

```text
这个物料批号分给了哪些生产批次？
哪些批次已经领用了它？
领用了多少？
有没有退料？
这些生产批次对应哪些工单和产品？
```

该视图比单纯的可用库存视图更接近追溯需求。

### 3.5.2 行粒度

建议行粒度为：

```text
一条物料使用记录
```

```text
batch_material_usage_id
```

```text
batch_material_usages
material_batches
products              -- 物料产品
production_batches
work_orders
products              -- 生产产品
users
```

| `usage_id` | 物料使用记录 ID |
| `material_batch_id` | 物料批次 ID |
| `material_batch_no` | 物料批号 |
| `material_product_id` | 物料产品 ID |

| `material_name` | 物料名称 |
| `supplier_name` | 供应商 |
| `protocol_code` | 技术协议编码 |

### 3.5.5 使用页面

| 页面 | 使用方式 |

### 3.5.6 注意事项

1. 该视图用于“物料批号 -> 生产批次”的正向追溯。
2. 如果需要进一步展示检验、返工、发货结果，可通过 `batch_id` 继续查询批次详情或时间线。
3. 一期不一定需要单独做完整 `v_forward_trace_material`，该视图已经可以满足大部分物料批号去向查询。

## 五、暂不建设的视图说明

### 5.1 暂不建 `v_product_detail`

产品资料完整视图虽然实用，但当前不是最痛点。产品资料查询主要关联：

```text
products
product_categories
process_routes
technical_files
```

联表复杂度较低，可先由后端接口直接查询。后续如果产品选择器、工单选择产品、物料批次选择物料等页面频繁重复同样字段，再抽成视图。

### 5.2 暂不建完整 `v_forward_trace_material`

一期先用 `v_material_batch_distribution` 实现：

```text
物料批号 -> 分配/领用的生产批次
```

如果后续要继续展示：

```text
生产批次 -> 检验 -> 返工 -> 发货
```

可通过 `batch_id` 继续查询批次详情或扩展追溯接口。

### 5.3 暂不建完整 `v_reverse_trace_batch`

反向追溯初期可由以下查询组合实现：

```text
v_production_batch_overview
v_batch_material_allocation
v_material_batch_distribution
batch_step_records
inspection_records
rework_records
finished_flow_records
```

如果后续需要客户审核专用页面，再考虑建设批次过程时间线视图。

## 六、最终建议

当前阶段建议先建设 5 个视图：

```text
1. v_batch_material_allocation
2. v_material_batch_available
3. v_production_batch_overview
4. v_process_route_step_detail
5. v_material_batch_distribution
```

其中第一批最先做：

```text
v_batch_material_allocation
v_material_batch_available
```

原因是它们能最快解决物料分配模块的大量重复联表和重复计算问题。

第二批做：

```text
v_production_batch_overview
v_process_route_step_detail
```

原因是它们支撑生产批次列表、任务生成、派工和报工。

第三批做：

```text
v_material_batch_distribution
```

原因是它支撑物料批号去向追溯，是追溯系统的核心能力之一。

最终原则：

```text
不为理论完整建视图，只为高频页面、重复联表、统一计算和追溯查询建视图。
```
