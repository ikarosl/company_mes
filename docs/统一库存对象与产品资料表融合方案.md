# 统一库存对象与产品资料表融合方案

> 本文档分析 `item_type`/`item_info` 与 `product_categories`/`products` 两对表做同样事情的问题，给出代码修改最小的融合方案。

## 一、问题识别

| 库存侧（新SQL方案） | 生产侧（已有实现） | 职责 |
|---|---|---|
| `item_type` | `product_categories` | 分类 |
| `item_info` | `products` | 对象/产品主数据 |

两对表字段高度重合，但用不同的 ID 体系，导致：
- 一个物料在系统中有两套 ID（`products.id` vs `item_info.id`）
- 库存流水、BOM、分配等都要维护两套引用
- 多了一套独立管理页面（`ItemsPage.vue`）

## 二、推荐方案：扩展 `products` + `product_categories`，删除 `item_info`/`item_type`

以**代码修改最小**为原则：保留已有生产侧表，向其中补充统一库存方案所需的字段，删除新库存方案中重复的表。

### 2.1 `product_categories` 扩展（替代 `item_type`）

现有的 `product_categories` 已经有 `product_attribute`（成品/半成品等）和 `product_type`（具体类型名）。新增一列即可对齐 `item_type.item_kind`：

```sql
ALTER TABLE product_categories
  ADD COLUMN item_kind VARCHAR(30) NULL COMMENT '库存对象大类：material/semi_finished/finished_product';
```

数据映射（一次性迁移）：
- `product_attribute = '成品'` → `item_kind = 'finished_product'`
- `product_attribute = '半成品'` → `item_kind = 'semi_finished'`
- 其余（如无product_attribute 的物料类） → `item_kind = 'material'`

### 2.2 `products` 扩展（替代 `item_info`）

现有的 `products` 已有 `product_model`（类似编码）和 `product_name`（名称）。新增库存方案需要的字段：

```sql
ALTER TABLE products
  ADD COLUMN item_code VARCHAR(100) NULL COMMENT '库存对象编码（兼容统一库存方案）',
  ADD COLUMN default_unit VARCHAR(20) NULL COMMENT '默认库存单位，
  ADD COLUMN status VARCHAR(20) NOT NULL DEFAULT '启用' COMMENT '启用/停用',
  MODIFY COLUMN unit VARCHAR(32) DEFAULT '个' COMMENT '生产单位';
```

数据映射：
- `item_code` ← 优先取 `product_model`（已有唯一性）
- `default_unit` ← 优先取 `unit`
- `status` ← 从 `TINYINT`（`0/1`）映射为 `启用`/`停用`

### 2.3 外键引用迁移

所有库存方案表中原指向 `item_info.id` 和 `item_type.id` 的外键，改为指向 `products.id` 和 `product_categories.id`：

| 表 | 需要变更的外键 |
|---|---|
| `product_bom` | `product_id` → `products.id`，`item_id` → `products.id` |
| `item_batch` | `item_id` → `products.id` |
| `inventory_transaction` | `item_id` → `products.id` |
| `stock_order_detail` | `item_id` → `products.id` |
| `production_item_demand` | `item_id` → `products.id` |
| `production_item_allocation` | `item_id` → `products.id` |
| `return_detail` | `item_id` → `products.id` |
| `item_scrap` | `item_id` → `products.id` |
| `stock_check_detail` | `item_id` → `products.id` |

### 2.4 视图重建

所有涉及 `item_info`/`item_type` 的视图改为使用 `products`/`product_categories`：

| 视图 | 变更 |
|---|---|
| `v_item_batch_stock` | `item_info` → `products`，`item_type` → `product_categories` |
| `v_item_batch_available_to_allocate` | 同上 |
| `v_production_item_demand_summary` | `item_info` → `products` |
| `v_production_batch_item_summary` | `item_info` → `products` |
| `v_production_batch_output_summary` | `item_info` → `products`，`item_type` → `product_categories` |
| `v_production_item_allocation_summary` | 无直接引用，无需改动 |

### 2.5 DDL 变更

修改 `20260629_apply_unified_inventory.sql` 迁移脚本：
- 移除 `CREATE TABLE item_type` 和 `CREATE TABLE item_info`
- `product_bom` 的 FK 改为指向 `products(id)` 和 `product_categories(id)`
- 其他表的 FK 改为指向 `products(id)`
