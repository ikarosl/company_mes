# 接口路由与权限常量开发规范

本文档用于约束后续接口、页面、菜单、按钮和权限开发，避免业务代码中散落接口路径和权限字符串。

## 一、核心原则

1. 公共接口路径必须抽离到 `packages/api-contract/src/routes.ts`。
2. 权限点常量必须抽离到 `packages/constants/src/permissions.ts`。
3. 前端页面、前端 API、后端 Controller、菜单、路由、权限种子都必须引用共享常量，不允许手写业务路径和权限编码。
4. `docs/接口路由+权限编码.md` 是人工可读的接口权限索引，必须与共享常量同步。
5. SQL 权限种子必须与 `packages/constants/src/permissions.ts` 保持一致。

## 二、接口路径抽离规则

接口路径分两层维护：

1. 基础资源路径放在 `BUSINESS_API`、`SYSTEM_API`、`AUTH_API` 等对象中。
2. 带参数或动作的路径放在模块级对象中，例如 `WAREHOUSE_API`。

示例：

```ts
export const BUSINESS_API = {
  warehouseOutboundOrders: '/warehouse/outbound-orders',
} as const;

export const WAREHOUSE_API = {
  outboundOrders: {
    root: BUSINESS_API.warehouseOutboundOrders,
    detail: (id: string) => `${BUSINESS_API.warehouseOutboundOrders}/${id}`,
    pick: (id: string) => `${BUSINESS_API.warehouseOutboundOrders}/${id}/pick`,
    confirm: (id: string) => `${BUSINESS_API.warehouseOutboundOrders}/${id}/confirm`,
    cancel: (id: string) => `${BUSINESS_API.warehouseOutboundOrders}/${id}/cancel`,
  },
} as const;
```

禁止：

```ts
url: `/warehouse/outbound-orders/${id}/confirm`
```

允许：

```ts
url: WAREHOUSE_API.outboundOrders.confirm(id)
```

## 三、权限常量抽离规则

所有权限编码只允许定义在 `packages/constants/src/permissions.ts`。

示例：

```ts
export const PERMISSIONS = {
  warehouse: {
    outboundOrders: {
      page: 'warehouse:outbound-orders:view',
      view: 'warehouse:outbound-orders:view',
      detail: 'warehouse:outbound-orders:detail',
      create: 'warehouse:outbound-orders:create',
      pick: 'warehouse:outbound-orders:pick',
      confirm: 'warehouse:outbound-orders:confirm',
      cancel: 'warehouse:outbound-orders:cancel',
    },
  },
} as const;
```

禁止：

```ts
@RequirePermission('warehouse:outbound-orders:confirm')
```

允许：

```ts
@RequirePermission(PERMISSIONS.warehouse.outboundOrders.confirm)
```

禁止：

```ts
meta: { permission: 'warehouse:outbound-orders:view' }
```

允许：

```ts
meta: { permission: PERMISSIONS.warehouse.outboundOrders.page }
```

## 四、新增接口必须同步的文件

新增或调整接口时必须同步以下位置：

1. `packages/api-contract/src/routes.ts`
   - 新增或调整公共接口路径。
   - 动作路径也必须抽离，例如 `confirm`、`cancel`、`enable`、`disable`。

2. `packages/api-contract/src/<module>.ts`
   - 新增请求 DTO、列表项、详情项、状态枚举等共享类型。

3. `packages/constants/src/permissions.ts`
   - 新增页面权限和接口动作权限。
   - 页面权限统一用 `page` 字段别名指向 `view` 权限。

4. `apps/backend/src/**/**.controller.ts`
   - 使用 `@RequirePermission(PERMISSIONS.xxx)`。
   - 禁止手写权限字符串。

5. `apps/admin-web/src/api/<module>.ts`
   - 使用 `packages/api-contract/src/routes.ts` 的公共路由对象。
   - 禁止手写业务 URL。

6. `apps/admin-web/src/router/routes.ts`
   - 页面路由 `meta.permission` 使用 `PERMISSIONS.xxx.page`。

7. `apps/admin-web/src/views/AdminLayout.vue`
   - 菜单权限使用同一个 `PERMISSIONS.xxx.page`。

8. `docs/接口路由+权限编码.md`
   - 补充菜单路由、菜单权限、接口路径、HTTP 方法、接口权限。

9. 权限 SQL 脚本
   - 初始化脚本或迁移脚本中必须补齐对应权限种子。
   - 权限编码必须和 `packages/constants/src/permissions.ts` 完全一致。

## 五、命名规则

权限编码建议使用：

```text
module:resource:action
```

示例：

```text
warehouse:outbound-orders:view
warehouse:outbound-orders:detail
warehouse:outbound-orders:create
warehouse:outbound-orders:pick
warehouse:outbound-orders:confirm
warehouse:outbound-orders:cancel
```

常见动作命名：

```text
view
detail
create
update
delete
enable
disable
submit
confirm
cancel
pick
adjust
complete
export
```

## 六、开发流程

新增接口建议按以下顺序：

1. 先在 `docs/接口路由+权限编码.md` 定义接口和权限。
2. 再在 `packages/constants/src/permissions.ts` 增加权限常量。
3. 再在 `packages/api-contract/src/routes.ts` 增加公共路由。
4. 再在 `packages/api-contract/src/<module>.ts` 增加共享类型。
5. 后端 Controller 使用公共权限常量。
6. 前端 API 使用公共路由常量。
7. 页面路由和菜单使用同一个页面权限常量。
8. 最后补权限 SQL 种子或迁移脚本。

## 七、检查清单

提交前必须检查：

```powershell
rg -n "RequirePermission\\('|" apps/backend/src
rg -n "permission: '" apps/admin-web/src
rg -n "url: `/.+\\$\\{|url: '/" apps/admin-web/src/api
```

这些命令不应命中新增业务代码。

同时执行：

```powershell
node node_modules\typescript\bin\tsc -p packages\api-contract\tsconfig.build.json
node node_modules\typescript\bin\tsc -p packages\constants\tsconfig.build.json
node node_modules\typescript\bin\tsc -p apps\backend\tsconfig.json --noEmit
```

## 八、评审要求

代码评审时发现以下情况必须退回修改：

1. 后端权限装饰器中手写权限字符串。
2. 前端路由或菜单中手写权限字符串。
3. 前端 API 中手写业务 URL 或动作 URL。
4. 新增接口没有同步 `docs/接口路由+权限编码.md`。
5. 新增权限没有同步 SQL 权限种子。
6. `packages/constants` 与数据库权限编码不一致。
7. `packages/api-contract` 路由常量与前后端实际路径不一致。
